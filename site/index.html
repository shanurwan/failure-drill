A free course, about half an hour

Break your API gateway on purpose, and measure what your callers felt.

Seven short lessons on failure drills for Tyk on Kubernetes. You type each command yourself. The terminal answers with the output of a real run, recorded on a lab cluster, and the picture beside it plays back what the system did second by second. Each lesson ends with a real incident of the same kind, and a link to the report written by the people it happened to.

    What the recorded runs showed

    Every number below is computed in your browser from the same records the terminal replays. Each drill was run several times, about 3,750 requests to each API per run. A range is the spread across runs.

    How it is measured

    Traffic that does not wait

    The tool sends a fixed number of requests every second to each address you give it, whether or not earlier ones have come back. A gateway that stalls shows up as slow answers and timeouts, the way it does for real callers. A test that waits politely for each answer would hide the stall.

    One clock, started at the fault

    Fifteen seconds of traffic run first, so there is a baseline to compare with. Every later time is counted from the moment the fault goes in. A failure before that moment is reported separately, because it means the baseline was not clean.

    Impact and longest gap

    Impact is the time from the first failed request to the last. Longest gap is the longest stretch in which every request failed. A drill can have a long impact and a short gap: a few failures scattered over several seconds.

    What this lab cannot tell you

    The lab is a single-node k3s cluster with open-source Tyk, so nothing here speaks for several nodes, several regions or a multi-data-centre setup. The numbers describe this lab on this day. Run the drills on your own install before you believe any of them about yours.

    Run it on your own cluster

    The tool is one Go binary. It needs a kubeconfig that may list and delete pods and patch the gateway Deployment in the namespace you point it at. Start in a cluster you are allowed to break.

    go install github.com/shanurwan/failure-drill/cmd/faildrill@latest

# read the install, change nothing
faildrill preflight -n tyk

# break one thing while traffic flows
faildrill run redis-primary --fault hang -n tyk \
  --url open=https://gw.example.com/status \
  --url keyed=https://gw.example.com/orders \
  --header 'keyed=Authorization: YOUR-KEY'

    No cluster to hand? The repository has a lab that brings up Redis with Sentinel and two gateways from Tyk's own chart: lab/up.sh.
